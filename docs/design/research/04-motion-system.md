# 04 — Motion system (web · macOS island · iOS)

**Bottom line:** keep motion calm and fast everywhere, and spend the "insane" budget on four rare moments: island bloom, verdict reveal, nudge drop and streak. Use one set of springs written as Apple `duration + bounce`, with the CSS `linear()` strings below computed from the same physics, so all three surfaces move the same way.

Sources: local skill notes (`emil-design-eng`, `review-animations/STANDARDS.md`), [animations.dev](https://animations.dev/), [Emil: Great animations](https://emilkowal.ski/ui/great-animations), [WWDC23 Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/) ([notes](https://wwdcnotes.com/documentation/wwdc23-10158-animate-with-springs/)), [WWDC23 Design dynamic Live Activities](https://wwdcnotes.com/notes/wwdc23/10194), [Rauno: Invisible details](https://rauno.me/craft/interaction-design), [Chrome: linear() easing](https://developer.chrome.com/docs/css-ui/css-linear-easing-function), [linear-easing-generator](https://linear-easing-generator.netlify.app/), [kvin.me CSS springs](https://www.kvin.me/css-springs).

## 1. Rules (apply before choosing a value)

1. **Frequency decides.** Things you see 100+ times a day, or that a keyboard triggers, get no motion (Emil, Rauno: "command menus skip fade"). Tens a day (hover, island hover-open) gets ≤300 ms with no stagger theatre. Rare moments (verdict, streak, onboarding) can delight.
2. **Ease-out for enter/exit, ease-in-out for moving on screen, `ease` for colour, linear for time.** Never use `ease-in` on UI.
3. **Never start from `scale(0)`.** Start at 0.94–0.97 with opacity 0. Popovers scale from their trigger. Modals and the lightbox stay centred.
4. **Interruptible by default.** Use CSS *transitions*, not keyframes, for anything a user can retrigger. On SwiftUI, springs keep their velocity when retargeted (WWDC23). Keyframes are only for fire-and-forget moments (confetti, shake).
5. **Exits are faster than enters:** exit = 0.6–0.7× the enter duration, with no bounce. The system responds fast. Only deliberate holds are slow.
6. **Bounce budget** (WWDC23): 0 = general purpose, 0.15 = subtle, 0.3 = noticeable. Never go above 0.4 on UI. 0.4 is for the mascot only.
7. **Blur bridges crossfades** (Emil): 2–8 px during a swap. The heaviest blur anywhere is 12 px.

## 2. Tokens

### Durations

| Token | Value | Use |
|---|---|---|
| `--dur-micro` | 120 ms | press scale, toggles, colour, focus ring |
| `--dur-small` | 180 ms | tooltip, popover, chip select, hover lift |
| `--dur-medium` | 260 ms | toast, card expand, step change, content blur-in |
| `--dur-large` | 420 ms | drawer/sheet, island morph (perceptual) |
| `--dur-celebrate` | 900–1400 ms | count-up, meter fill, confetti. The whole sequence is capped at 2.6 s and can be skipped |
| exit | 0.65 × enter | e.g. toast 260 → 170 ms |

### Easing curves

| Token | CSS | SwiftUI |
|---|---|---|
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | `.timingCurve(0.23, 1, 0.32, 1, duration: d)` |
| `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | `.timingCurve(0.77, 0, 0.175, 1, duration: d)` |

| `--ease-time` | `linear` | `.linear(duration: d)` |

### Springs (single source of truth)

Mapping: `.spring(response: r, dampingFraction: f)` ≡ `.spring(duration: r, bounce: 1 − f)` for bounce ≥ 0. Physics: mass 1, stiffness `(2π/d)²`, damping `4π(1−bounce)/d` ([WWDC23](https://developer.apple.com/videos/play/wwdc2023/10158/)). The CSS strings were generated by simulating that exact spring. **The CSS duration is the settle time, which is longer than the perceptual duration** (same convention as [kvin.me](https://www.kvin.me/css-springs)). In SwiftUI, write the explicit `.spring(duration:bounce:)` rather than trusting preset defaults.

| Token | SwiftUI | Overshoot | CSS duration | Use |
|---|---|---|---|---|
| `spring-micro` | `.spring(duration: 0.25, bounce: 0)` | 0 | 376 ms | toggles, chip select, dot recolour |
| `spring-snappy` | `.spring(duration: 0.35, bounce: 0.15)` | 0.6 % | 484 ms | popovers, wings, composer send, tickers |
| `spring-smooth` | `.spring(duration: 0.5, bounce: 0)` (= `.smooth`) | 0 | 686 ms | collapse, sheets, ring start |
| `spring-island` | `.spring(duration: 0.45, bounce: 0.2)` → `response 0.45, dampingFraction 0.8` | 1.5 % | 619 ms | notch → panel, alert drop |
| `spring-bouncy` | `.spring(duration: 0.5, bounce: 0.3)` | 4.5 % | 720 ms | verdict pill, streak bump, sample dot pop |
| `spring-celebrate` | `.spring(duration: 0.6, bounce: 0.4)` | 9.4 % | 1003 ms | mascot only |

```css
:root{
  --ease-out:cubic-bezier(.23,1,.32,1); --ease-in-out:cubic-bezier(.77,0,.175,1); --ease-drawer:cubic-bezier(.32,.72,0,1);
  --spring-micro:var(--ease-out); --spring-snappy:var(--ease-out); --spring-smooth:var(--ease-out);

}
/* var() hides an invalid linear() until computed time, so a plain fallback line won't work. Gate it instead. */

```

`linear()` support: Chrome/Edge 113, Firefox 112, Safari 17.2 ([Chrome docs](https://developer.chrome.com/docs/css-ui/css-linear-easing-function)).

### Stagger

- Enter only: **40 ms per item, capped at 6 items (240 ms)**. Items after the sixth arrive together with the sixth. Each item moves translateY 6 px → 0 with opacity, using `--dur-medium --ease-out`.
- Exits never stagger. The whole group leaves together in 120–170 ms.
- Stagger never blocks input. Elements are clickable from frame 0.
- Island content: at most 3 tiers (header, chips, card) at 30 ms. It opens tens of times a day.

### Reduced motion (fewer and gentler, not zero)

The current `index.html:719` kills everything (`*{animation:none!important;transition:none!important}`). Replace it with:

```css
@media (prefers-reduced-motion: reduce){
  :root{--spring-micro:ease;--spring-snappy:ease;--spring-smooth:ease;--spring-island:ease;--spring-bouncy:ease;--spring-celebrate:ease}
  *,*::before,*::after{animation-duration:1ms!important;animation-iteration-count:1!important;scroll-behavior:auto!important}
  .moves{transform:none!important}           /* keep opacity/colour crossfades at 150ms */
  .confetti,.flame-flicker,.shake{display:none}
}
```

- Count-ups jump straight to the final value (this is already done at `index.html:1070`).
- SwiftUI: `@Environment(\.accessibilityReduceMotion) var rm` → `rm ? .easeOut(duration: 0.15) : .spring(...)`. Use `.opacity` transitions instead of scale/blur. Skip `.shake`, confetti and idle flicker. Haptics stay.

### Performance rules

- Animate only `transform` and `opacity`. `filter: blur` is allowed on elements no bigger than 440×600 px and only while the swap runs. Never animate `backdrop-filter`.
- **Fix existing layout transitions:**
  - `.track .decl/.ver`, `.hbar .v` and `.vmeter .f` all use `transition: width`. Switch them to `transform: scaleX(p)` with `transform-origin: left`. The rounded ends can be kept with an inner 100%-width bar plus an `overflow:hidden` wrapper.
  - `.detail` uses `grid-template-rows`. That is acceptable because it is rare.
- Set `will-change: transform` only during the animation (add it on start, remove on `transitionend`).
- Don't drive child transforms with a CSS variable on the parent, because it forces a style recalc for every child.
- Particles: at most 32 per burst, using WAAPI (`el.animate`), with nodes removed in `finish`.
- SwiftUI: draw particles in one `Canvas` inside `TimelineView(.animation)` and stop the timeline after the burst. Use `.drawingGroup()` on the mascot. Don't apply `.blur` to the island's black backing shape, only to its content.
- **Island today** uses 6 different ad-hoc springs (`Island.swift:354, 382, 789–792, 1631, 1701, 1710`). Replace them with `spring-island` for opening and alerts, `spring-smooth` for collapsing and `spring-snappy` for inner content.

## 3. Island morph choreography (Dynamic Island model)

Apple's Live Activities guidance: the island should feel alive, with continuously updating data, rounded thick shapes and heavy, legible text ([WWDC23 10194](https://wwdcnotes.com/notes/wwdc23/10194)). Rauno adds that motion keeps momentum and stays spatially consistent: it comes from, and returns to, its source ([Invisible details](https://rauno.me/craft/interaction-design)).

**Open** (hover dwell 0.35 s, or a click):

| t | Shape | Content |
|---|---|---|
| 0 | black shape: frame + corner radius (10 → 22 pt) on `spring-island`, anchored at the notch top centre | old compact wings: opacity → 0, blur 0 → 4, scale → 0.9 in 100 ms |
| 60 ms | | new panel content: opacity 0 → 1, blur 8 → 0, scale 0.94 → 1 (anchor `.top`) on `spring-snappy` |
| +30 ms per tier | | header → chips → card |

**Close:**
- Content leaves first: 100 ms, opacity plus blur 4.
- The shape then collapses on `spring-smooth`, with **no bounce**, because overshooting inside the hardware notch reads as a glitch.

**Hotkey ⌥⌘A:** the same shape spring at `duration 0.3`, with no blur or stagger, because it is keyboard-triggered.

```swift
content.transition(.asymmetric(
  insertion: .opacity.combined(with: .scale(0.94, anchor: .top)).combined(with: .blurReplace)
             .animation(.spring(duration: 0.35, bounce: 0.15).delay(0.06)),
  removal:   .opacity.combined(with: .blurReplace).animation(.easeOut(duration: 0.1))))
```

`.blurReplace` needs macOS 14 / iOS 17. Build the shape as one `RoundedRectangle` whose frame animates. Don't cross-fade two shapes.

## 4. Signature moments for the demo (14)

1. **Island bloom.** The notch → panel morph described in §3. This is the opening shot of the video.
2. **Live wings.** When a session starts:
   - The wings slide out from under the notch: x ±24 pt → 0 with opacity, on `spring-snappy`. The right wing follows 60 ms after the left.
   - The value uses `.contentTransition(.numericText(countsDown: true))` with `.monospacedDigit()`.
3. **Composer send morph.** On Enter or click:
   - The button presses to scale 0.97 (120 ms).
   - The typed text blurs 2 px and fades (150 ms).
   - The field morphs into the session card on `spring-snappy`.
   - Web: FLIP (measure both rects, apply the inverse `transform`, then transition to `none`). SwiftUI: `matchedGeometryEffect(id: "composer", in: ns)`.
4. **Ring timer.**
   - Start: the arc draws 0 → p on `spring-smooth`.
   - Running: each second ticks on `linear 1000ms`. Use SVG `stroke-dashoffset`, which is fine for one 120 px ring.
   - Final 60 s: the accent-ink glow breathes, opacity 0.6 ↔ 1 on a 2.4 s cycle.
   - SwiftUI: `Circle().trim(from: 0, to: p).animation(.linear(duration: 1), value: p)`.
5. **Polaroid sample.** A new frame enters the strip with translateY 6 → 0 and opacity (260 ms). It then "develops" over 1200 ms `--ease-out`:
   - `filter: grayscale(1) brightness(1.5) blur(6px)` → `none`. This is fine at 64 px thumbnails.
   - The verdict dot then pops: scale 0.6 → 1 on `spring-bouncy`.
   - SwiftUI: `.saturation(0) .brightness(0.4) .blur(6)` → `1 / 0 / 0` with `.easeOut(duration: 1.2)`.
6. **Nudge drop.**
   - The alert drops out of the notch on `spring-island`. At 180 ms after landing it does one shake: translateX `0,-6,5,-3,2,0` px over 360 ms, `ease-out`. This is a keyframe animation, which is fine here because it is fire-and-forget.
   - Only "bad" drift (phone) gets the shake. Soft drift gets no shake.
   - The mascot pops in with a worried pose. On iOS add `.sensoryFeedback(.warning, trigger:)`.
7. **Verdict reveal.** This is the hero moment. Budget 2.6 s, and a click skips to the end.
   - t0: the card rises 12 px with opacity on `spring-smooth`.
   - 150 ms: the verdict pill blurs in on `spring-bouncy`.
   - 300 ms: the percentage counts up from 0 over 900 ms with easeOutCubic in rAF and `font-variant-numeric: tabular-nums`. The meter fills (`scaleX`) over the same 900 ms.
   - 1200 ms: the mascot celebrates and the confetti fires. iOS plays `.sensoryFeedback(.success)`.
   - **Partial:** no confetti, and the mascot shrugs.
   - **Slacked:** a red meter, the mascot slumps, no shake and no confetti. Don't punish.
8. **Claw confetti.**
   - 28 particles: tiny claw paths, 4-point sparks and 3 px dots.
   - Colours: `#76B900` 50 %, `#8FD400` 25 %, `#FFF` 15 %, `#F2A900` 10 %.
   - They burst in a 60° cone from the mascot's claws.
   - WAAPI, each particle: `translate(dx, -h)` → `translate(1.4dx, g)` with gravity done as 3 keyframes, rotate ±240°, opacity fading over the last 30 %. Durations are randomised 1100–1600 ms on `cubic-bezier(.2,.6,.4,1)`.
9. **Number tickers.** Totals and the pace grid roll their digits.
   - Web: each digit is a column of 0–9 moved by `translateY(-n*1em)` on `spring-snappy`, inside an `overflow:hidden` box 1em tall.
   - SwiftUI: `.contentTransition(.numericText(value: v))` inside `withAnimation(.snappy)`.
10. **Streak flame.**
    - On increment: scale 1 → 1.18 → 1 on `spring-bouncy`, and the number rolls.
    - Idle: three SVG flame layers flicker with scaleY 0.96 ↔ 1.04 at 1.8 / 2.3 / 2.9 s (`ease-in-out`, alternate, `transform-origin: bottom`). Pause it when off-screen (IntersectionObserver) and under reduced motion.
    - iOS/island: `Image(systemName: "flame.fill").symbolEffect(.bounce, value: streak)`.
11. **Drawer / sheet physics.**
    - Web Setup drawer: enter `transform 420ms var(--ease-drawer)`, exit 260 ms.
    - Drag-to-close dismisses when distance > 30 % or velocity > 0.11 px/ms. Over-drag uses friction: `d' = d * 0.2`. Use `setPointerCapture`.
    - iOS: native `.sheet` + `.presentationDetents([.medium, .large])` gives this physics for free.
12. **Card hover lift.**
    - Under `@media (hover:hover) and (pointer:fine)`: translateY(-2px) in 180 ms `--ease-out`. The shadow change is an opacity fade on a `::after` layer, so the shadow itself never animates.
    - Press: scale 0.98 in 120 ms.
    - The press is also the only "hover" on iOS: `.scaleEffect(pressed ? 0.97 : 1)` on `spring-micro`.
13. **Skeleton without the shimmer.** Placeholders breathe: opacity 0.5 ↔ 0.8, 1.6 s, `ease-in-out`. A sweeping shimmer is too busy for the calm Claude feel. When data arrives, the content blurs in (blur 4 → 0, opacity, 240 ms) while the placeholder fades out in 120 ms.
14. **Correct-a-sample popover.**
    - It scales 0.96 → 1 with opacity in 160 ms `--ease-out`, with `transform-origin` set to the clicked dot. That origin is a fixed `bottom center` today, which is only correct when the popover sits above the dot.
    - On save: the dot colour crossfades on `spring-micro`, the on-task % ticks (moment 9), and the mascot nods with rotate ±4° twice over 400 ms.

The onboarding steps follow the same grammar: directional x ±24 px plus 4 px blur, 280 ms out / 320 ms in, with the progress bar on `spring-smooth`.

**Mascot motion.** Use the same tokens; the visual design is in a separate doc.
- Idle: breathing scaleY 1 ↔ 1.02 over 4 s, and a blink (120 ms) at random 3–6 s intervals.
- Happy hop: translateY -10 px on `spring-celebrate`.
- Worried: a tilt of -6° on `spring-snappy`.
- Slump: translateY +4 px and the eyes droop, on `spring-smooth`.
- Every reaction is a transition between poses, so a new event retargets mid-pose instead of restarting.

## 5. Do / don't

| Do | Don't |
|---|---|
| One spring vocabulary on three platforms | Hand-tuned springs per view (the island has 6 today) |
| `transform: scaleX` meters | `transition: width` (`index.html:137, 138, 362, 540`) |
| Blur 2–8 px to bridge swaps | Blur over 12 px, or animating `backdrop-filter` |
| Celebrate rare events only (verdict, streak) | Confetti on every sample, or bounce on hover |
| Exits at 0.65× with no bounce | Bouncing into the hardware notch |
| Reduced motion = opacity fades | A blanket `animation:none` that removes comprehension cues too |
